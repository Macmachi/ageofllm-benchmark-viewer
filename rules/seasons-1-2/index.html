Rules history: Seasons 1 and 2

Last updated November 2026

FROZEN Both seasons are over and their rules are frozen. No further match will be played under them. Known defects are documented on this page rather than fixed, so that every published match can be replayed exactly as it was played.

Seasons 1 and 2 of Age of LLM were played on the same game: a turn-based strategy duel in which two language models face each other on a small map, with no strategic advice. Between May and October 2026 its rules, its scoring and the system prompt given to the models changed several times. This page records those changes, version by version, so that each match can be read against the rules it was played under.

Season 3 (Robot Duel) is a different game, with its own rules and version numbers, and is not covered here.

Versions and sources

The game engine version. Every match replay records the game engine version it was played on. That number changes only when something that could make a match go differently changes: the rules, the system prompt, what each player is shown about the game, or how its actions are checked. Changes to the website and to the tools that run matches carry a separate site version, which never appears in a replay. Until August 2026 a single number covered both, which is why two engine numbers (0.16.1 and 0.16.2) were raised without any change to the rules.

The system prompt is the fixed text sent to every model with each request. It states the rules, the scoring and the reply format. With it, each turn, the model receives the state: a description of the game as that player can see it.

Sources. This page is compiled from the release notes written when each version was published. The engine's preserved source history begins with version 0.15.0: from that version on, every statement below was also checked against the engine code and the prompt text, and quotations of the prompt are exact. For versions 0.9.2 to 0.14.0 only the release notes are available, and their statements could not be re-checked against the code. One test copy of the 0.14.0 engine has also been preserved. It was prepared for scenario tests and differs in places from the version used in matches (for example, it has no free-text message channel), so it is cited only for sentences it shares with 0.15.0.

Match counts below are taken from the version recorded in each published replay. Quotations keep the prompt's capital letters; [...] marks a passage left out.

  • The first version on which ranked matches were played. No release note describes it as a change; its rules are known through what later versions changed. Before 0.10.0, for example, the map layout was fixed, attacks were not blocked by obstacles and mines could only be built in a player's own territory; before 0.11.0, a base had 8 hit points.
0.9.3May 2026 Season 1 · 8 matchesrelease notes
  • No release note describes what changed from 0.9.2.
0.9.4May or June 2026 no matchrelease notes
  • Scoring: a player who accepts an ultimatum loses the match but now scores 0.5 points instead of 0 (an ordinary defeat scores 0). The prompt, the scoring and the replay viewer's legend were updated together.
  • Fog-of-war memory: a destroyed enemy building is removed from each player's list of remembered buildings, so the state no longer shows it as still standing.
  • No match was played on this version; the next Season 1 matches were played on 0.10.0.
0.10.0June 2026 Season 1 · 4 matchesrelease notes
  • Line of sight: a ground attack (tank or SAM) fails if a mountain or a building lies on the straight line between the attacker and its target. Air attacks (fighter) are not blocked. The target's own cell never blocks.
  • Mines on either half: a mine can be built on any matching deposit that is free and in view, including on the opponent's half. An intact enemy mine cannot be captured: it must first be destroyed, or its deposit run out. The silo can still only be built in a player's own territory.
  • Terrain varies by match: the central mountain barrier, its passages and the central uranium deposit are generated from each match's seed, and a few extra mountains are placed inside each territory, mirrored between the two sides.
  • Mine costs: credit and uranium mines from 1 to 2 credits; the central mine from 2 to 3 credits.
  • Finite deposits: a credits deposit holds 18 units and a uranium deposit 16. An exhausted deposit disappears with its mine, and a new deposit of the same kind appears elsewhere on the same side.
  • Prompt and state: the prompt no longer gives a fixed map layout and describes line of sight, the new costs and depletion. The state now includes the reserve left in each visible deposit.
0.11.0June 2026 Season 1 · 17 matchesrelease notes
  • Base hit points from 8 to 4. A tank hit removes 2 hit points, so a base now falls to two hits instead of four. Unit hit points do not exist in this game: any successful attack destroys a unit.
  • Prompt: the line-of-sight rule is spelled out, with the exact message the engine returns ("Line of sight blocked by a mountain or building"), and states that a target in range is not enough if the line to it is blocked.
  • Other changes in this release concern how matches are run (a longer time limit per request, automatic saving and resuming). They do not change the rules.
0.12.0June 2026 Season 1 · 8 matchesrelease notes
  • SAM movement from 1 to 2 cells per turn, the same as a tank.
  • Central mine cost from 3 to 4 credits.
  • Uranium deposit reserve from 16 to 12 units.
  • Map fairness: extra mountains are no longer placed in the column next to the central barrier on either side, so a passage through the barrier cannot be blocked on one side only.
0.13.0June 2026 no matchrelease notes
  • Prompt: explains that a player's actions are applied one by one, in the order listed, each on the board left by the previous one. For example, moving a unit away can remove the view that a later build in the same reply needed.
  • A scripted reference opponent was added to the software. It played no Season 1 or Season 2 match.
0.14.0June 2026 Season 1 · 9 matchesrelease notes
  • Deposits on the opponent's half: once seen, such a deposit is remembered and listed in the state (kind, position, reserve, turn last seen). Before, these deposits were never shown, even when in view. Building a mine on one still requires the cell to be in view at that moment, and an exhausted deposit is dropped from memory.

  • Prompt unchanged. It still said that a launch could not be seen or answered by the opponent.
  • The earliest version whose engine code and prompt text are preserved.

The release notes describe them as the last two residual hints in the prompt.   • The mirror campaign was played on 0.16.1: one model against itself, to measure whether either side of the map was favoured. It is a measurement campaign, outside both seasons and every ranking. It therefore used the 0.16.0 prompt, including the sentence that ruled out any reaction to a launch.
0.17.0August 2026 Season 2, opening · 12 matchesrelease notes, checked against source
  • New units wait one turn: a unit produced in a turn cannot move or attack until its owner's next turn, the same one-turn delay that already applied to buildings. The engine chooses its cell and its identifier, and both appear in the next state. This replaced the earlier statement that a new unit could act at once (see Using a unit the turn it is produced).
  • Fog of war in build checks: a build aimed at a cell out of view is now refused for that reason first, so the refusal no longer reveals whether a building stands there (see Building into the fog).
  • Prompt: seven phrases of advice removed, together with the mentions of which failures "count as illegal" (listed under Advice removed from the prompt).
  • Statistics only: a refusal caused by something the player could not see, such as moving onto a hidden enemy unit, is recorded as such and counted apart from illegal actions. This does not change the game.
  • A paused match can no longer be resumed under a different engine version.
  • Used only for the 12 opening matches of Season 2; every later match was played on 0.18.0.
0.18.0August 2026, in use until October 2026 Season 2, challenges · 32 matchesrelease notes, checked against source
  • Prompt: the sentences ruling out any reaction to a launch are removed, and the launch alert is described. See The nuclear launch alert.
  • Prompt: the length of a ceasefire is spelled out (a ceasefire accepted on turn T is in force on turns T to T+3). The engine was not changed.
  • Prompt: the bomb-cost schedule is listed in full (23 uranium from turn 40, then 21, 19, 17, and 15 from turn 80), with the statement that the 13-unit floor is not reached in an 80-turn match. The engine was not changed.
  • Replays now record, for each player and turn, the alert value the player was given before deciding, and the turn until which a ceasefire is in force. The replay viewer shows both.
  • Game behaviour is unchanged: only the prompt text and the contents of the replays changed. All three prompt corrections were in place before the first match on this version.
  • Played: the 18 challenge matches of The Ladder (August 2026) and the 14 matches of The Throne (September to October 2026).
  • One challenger of The Throne, Jev 1.13 (two matches, September 2026), is not a chat model. It played through a separate interface of typed choices, with the same engine version, the same rules text and the same state, but without free-text messages.

  • Mutual destruction is scored 0 for both players in the prompt (in every preserved version) and in the Season 1 table. In Season 2, the program that scored the ladder's matches counted it as a draw, 1 point each, until site version 0.17.5 (August 2026), when it was corrected to 0. The release notes state that one two-match tie had been scored under the old rule and that its outcome did not change.
  • Season 1 ranking: models were ranked by average points per match, then win rate, then head-to-head results between the tied models, then fewer turns to win, then number of matches, then total points. Models with fewer than 3 matches were listed after the others as provisional.
  • Season 2, opening: four models played each other twice, once from each side (12 matches). The table was ranked on points, then wins, then head-to-head results between the tied models, then the average number of turns taken to win (fewer first), then the average number of turns taken to lose (more first). Its top four took the four places of the ladder.
  • Season 2, challenges: every challenge is a tie of two matches with the sides swapped. The tie is decided on points. If the points are level and each model won one match, the model that won its own match in fewer turns takes the tie (decided on speed). If neither model won a match, or both won in the same number of turns, the model already in place keeps it. This rule applied from the first challenge.
  • The Ladder (August 2026): a challenger first played the fourth place; each tie it won moved it up to face the next place, and its climb stopped at the first tie it did not win. The Throne (from September 2026): a challenger plays the reigning champion and nobody else. The tie rule is the same in both formats.
  • Published label: the Season 2 data file states the tie rule as "incumbent_retains". That label names only the last fallback; the rule applied compares speed first, as described above.

The nuclear launch alert

What the engine does (from 0.15.0, June 2026)

From game engine 0.15.0, the state each player receives contains a field named enemy_launch_detected. It is true when two conditions hold at the moment the player is asked to decide: the opponent has launched a bomb earlier in the same turn, and at least one of the opponent's silos is inside the player's current field of view. Otherwise it is false and the launch stays invisible. The field never says whether the opponent is able to launch: uranium stays secret.

Who can receive it. Each turn, both players take one half-turn. Who plays first is drawn at random for the first turn and then alternates every turn. Launches are resolved at the end of the turn, after both half-turns, and the record of the launch is cleared at that point. The alert can therefore only reach the player who plays second in the turn of the launch, and only if that player can see one of the launcher's silos. The player who plays first can never receive it.

What it allows. A bomb cannot be stopped. The only possible response is to launch in the same half-turn, which requires an operational silo, enough uranium for the current bomb cost, and the opponent's base already discovered. Two launches in the same turn produce a mutual destruction (both lose, 0 points each) instead of a nuclear defeat for the player who did not launch. Because a launch always ends the match at the end of its turn, the alert can only ever be true on the last half-turn of a match.

What the prompt said before 0.18.0

Launches are SIMULTANEOUS and resolved by the engine at the END of the turn, after BOTH players have played. A bomb fired this turn is "in flight": because uranium and launches are SECRET, the opponent does NOT see it and cannot consciously react. There is no manual retaliation.

System prompt, section "SIMULTANEOUS NUCLEAR LAUNCH", game engine 0.15.0, 0.16.0 and 0.17.0 (and so 0.16.1).

Whether you play first or second this turn does not change this: the opponent could already have a ready bomb

Same section, same versions. The sentence continued "Launching is a calculated risk, not a guaranteed win." up to 0.16.0, and ", and you cannot observe it." in 0.17.0.

  • The prompt did not describe the new field. The release notes of 0.15.0 state that the prompt was left unchanged on purpose, on the reasoning that "the model discovers the signal directly in its state".
  • The preserved test copy of the 0.14.0 engine carries the same sentence and has no alert field: before 0.15.0 the sentence matched what the engine did. Whether it was present before 0.14.0 cannot be checked.
  • Matches played with the alert in the engine and this sentence in the prompt: those on 0.15.0 (Season 1, 2 matches), on 0.16.1 (mirror campaign, 57 matches) and on 0.17.0 (Season 2 opening, 12 matches).

What changed in 0.18.0 (August 2026)

The sentences above were removed. The same section now reads, after the description of simultaneous launches:

A bomb cannot be intercepted: there is no defence against one already fired. The ONE thing you can do is fire back the same turn, and for that you must first know a launch happened [...]. Whether the warning reaches you depends on what you can SEE.

System prompt, section "SIMULTANEOUS NUCLEAR LAUNCH", game engine 0.18.0.

and the section on fog of war gained this paragraph:

NUCLEAR EARLY WARNING: "enemy_launch_detected" is true when the enemy has launched a bomb THIS turn AND one of their silos is currently in your field of view. Without that line of sight the launch stays secret. It can only ever be true for whoever plays SECOND in the turn (the engine alternates who plays first), and it never tells you whether the enemy CAN launch [...]. If it is true and you are able to launch this turn, launching makes it mutual destruction (0 pts each) instead of your defeat.

System prompt, section "FOG OF WAR", game engine 0.18.0.

  • The mechanism itself did not change in 0.18.0: only its description.
  • From 0.18.0, each replay records the alert value the player was given before deciding. Replays of earlier versions do not record it, so for those matches it can only be reconstructed from what each player could see.

Where the prompt and the engine disagreed

The prompt is the only description of the rules a model receives. The cases below are those where it said something the engine did not do, or left out something the engine did. Unless stated otherwise, each is confirmed in the preserved source, that is from 0.15.0 onward; whether it already existed in earlier versions is not known. Two further differences concern scoring rather than the engine (mutual destruction on the ladder, and the published tie-rule label); they are described under Scoring and ranking.

1. Reacting to a launch

Prompt
"the opponent does NOT see it and cannot consciously react. There is no manual retaliation." (0.15.0 to 0.17.0)
Engine
The player who plays second could be told of the launch and could answer it with its own launch the same turn, turning a defeat into a mutual destruction.
Status
Prompt corrected in 0.18.0. See The nuclear launch alert.

2. Length of a ceasefire

Prompt
"No attacks for 3 turns", "neither side may ATTACK for 3 turns" and "The ceasefire ends automatically after 3 turns; combat is allowed again afterwards." (0.15.0 to 0.17.0, and in the 0.14.0 test copy)
Engine
A ceasefire accepted on turn T is in force on turns T, T+1, T+2 and T+3: the rest of the turn it is accepted on plus three full turns. Attacks are allowed again from turn T+4.
Status
Prompt corrected in 0.18.0; the engine kept its behaviour.

3. Lowest cost of the bomb

Prompt
"PRESSURE after turn 40: cost drops 2U every 10 turns (floor 13U)." (0.15.0 to 0.17.0, and in the 0.14.0 test copy)
Engine
The first reduction applies on turn 40 itself (from 25 to 23 uranium). The 13-unit floor is only reached on turn 90, after the 80-turn limit, so the lowest cost reachable in a match was 15.
Status
Prompt corrected in 0.18.0; the engine kept its behaviour.

4. Using a unit the turn it is produced

Prompt
"A unit produced this turn CAN move and attack the same turn." (0.15.0 and 0.16.0, and in the 0.14.0 test copy)
Engine
The engine chose the new unit's cell and gave it an identifier from a counter shared by both players, and reported both only after the whole reply had been executed. Since a model sends all its actions for the turn in one reply, it could not reliably refer to the new unit in that reply.
Status
Resolved in 0.17.0 by changing the rule: a new unit acts from its owner's next turn.

5. Building into the fog

Prompt
"You can only BUILD on a cell currently in your FIELD OF VIEW" (all preserved versions)
Engine
Before 0.17.0, the engine checked whether the cell already held a building before checking whether the player could see it. A build aimed at an unseen cell holding a building was refused with "Cell already has a building", which revealed that building.
Status
Fixed in 0.17.0: visibility is checked first.

6. Three actions per turn

Prompt
"Maximum 3 actions per turn." The state also gives "actions_per_turn": 3. (All preserved versions)
Engine
The limit was not applied to language models: every action in a reply was executed, however many there were.
Status
Never corrected; the rules are frozen.

7. Line of sight in both directions

Prompt
A ground attack is blocked "if a mountain OR a building lies on the straight line between the shooter and its target". (Line of sight exists since 0.10.0.)
Engine
The engine traces the cells from the shooter to the target. The trace from B to A does not always cross the same cells as the trace from A to B, so with a mountain next to the line one side can fire and the other cannot. Smallest case found: from (0, 0) to (1, 2), with a mountain at (0, 1), the shot is blocked; from (1, 2) to (0, 0), it is not. The same trace is used in every preserved version, including the 0.14.0 test copy.
Status
Never corrected; the rules are frozen.

8. A tank victory in a launch turn

Prompt
Lists "You bring the enemy base HP to 0 with tanks" as a military victory, and gives a mutual destruction only when "Both players launch on the SAME turn" (all preserved versions). It also tells the player facing a launch that there is nothing else to do: "There is no manual retaliation" (0.15.0 to 0.17.0), then "The ONE thing you can do is fire back the same turn" (0.18.0).
Engine
If a tank destroys the base of a player who has already launched a bomb earlier in that turn, the bomb still lands and the result is a mutual destruction, not a military victory. This gives the player facing a nuclear defeat a second way, besides launching back, to turn it into a mutual destruction. No preserved version of the prompt states this case. The same rule is in every preserved version of the engine, including the 0.14.0 test copy.
Status
Never corrected; the rules are frozen. The case never occurred in a published match: every mutual destruction of Seasons 1 and 2 came from two launches in the same turn.

One other known defect: a reply whose list of actions contains a bare word (for example ["wait"] instead of [{"type": "wait"}]) stops the program running the match with an error, instead of being refused as an invalid action.

Advice removed from the prompt

The prompt is meant to describe the rules, the scoring and the reply format, and nothing about how to play. Two releases removed sentences that went beyond that.

0.16.0 (June 2026)

  • "Push tanks + a scout into enemy ground to contest their economy."
  • "Scout with a drone early."

0.17.0 (August 2026)

The release notes count seven phrases of advice, removed while keeping every payoff and mechanic they mentioned:

  • "So accepting a hopeless position is rewarded over fighting on." (with "surrendering a lost position is rewarded" in the description of the ultimatum)
  • "So a mine is not forever: keep scouting, and be ready to relocate and rebuild when a deposit runs dry."
  • "Launching is a calculated risk, not a guaranteed win."
  • "factor the 2 C rebuild cost into raids and defence."
  • "Defend fresh builds [...]"
  • "position yourself for when it ends." (about a ceasefire)
  • "Use it to judge whether the opponent is honest, bluffing, or has broken earlier promises [...]" (about the history of messages and proposals)

Also removed or reworded in 0.17.0:

  • two mentions that a failed action "counts as illegal" or "counts as an illegal action";
  • the remark that a blocked line of sight is "the most common reason a ground attack is rejected";
  • the description of a refused ultimatum as "only psychological pressure backed by the proposer's real board position", replaced by "no mechanical effect of any kind";
  • "A unit produced this turn CAN move and attack the same turn.", replaced by the new deployment rule (see 0.17.0).
